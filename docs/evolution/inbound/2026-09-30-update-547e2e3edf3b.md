# Relatório de update — e a KB de vocês corrigiu o core no mesmo dia

Quatro levas do core entraram hoje. O que muda para quem trabalha aqui, e o que **veio deste repo**.

## 1. Zoho Projects é provider do task manager

`TASK_MANAGER_PROVIDER=zoho`, adapter em `.claude/utils/task-manager/adapters/zoho.md`, com os 16
membros da interface. Escrito a partir de sondas de escrita contra portal real, não por analogia.

A regra de desenho, porque ela decide como se programa contra essa API: **a Zoho aceita parâmetro,
devolve 2xx e ignora em silêncio**. Seis casos medidos (`?search=`, `?parent_task=`, `milestone_id`,
`owners`, `owner`, `depth`). Portanto: **verifique no CORPO da resposta, nunca no código HTTP**. Todo
vínculo é **objeto aninhado**.

## 2. A KB de vocês corrigiu o core — e isto é o item mais importante deste relatório

Ao preparar esta entrega, comparei a KB `platforms/zoho-projects-api.md` daqui com a do core e vi que
**a de vocês estava mais nova**: v1.2, com `/api/v3.1/`, `global-statuses` e o escopo
`custom_fields.READ`. Nela havia uma linha que o core não tinha:

```
parental_info.parent_task_id  →  cria subtarefa
```

Sondei contra o portal real na hora e **funciona**: a filha nasce `depth: 1` e o pai passa a
`association_info.has_subtasks: true`, conferido no corpo.

O core estava errado, e errado **duas vezes no mesmo dia**: primeiro afirmando que a V2 entregava
subtask (com base num `201` que ninguém abriu — a task nascia rasa), depois afirmando que **não havia
caminho nenhum** — porque só as formas **planas** foram testadas. O arquivo já dizia, em caixa alta,
que todo vínculo é aninhado. A correção está em `547e2e3e` e o mecanismo que impede a recaída é um caso
de bancada que cobra a **forma aninhada** em vez de canonizar a conclusão da vez.

**Consequência prática:** `createSubtask` funciona, e `getSubtasks` filtra no cliente por
`parental_info.parent_task_id`.

## Para usar o Zoho

Configure `ZOHO_CLIENT_ID`, `ZOHO_CLIENT_SECRET` e `ZOHO_PORTAL_ID` (o `.env.example.onion` traz o
bloco, com o datacenter opcional). O caminho é **Self client + `client_credentials`**, que dispensa
grant code e refresh token. **Não há MCP nativo** da Zoho para Projects — transporte só API, e isso é
pesquisado, não medido, como está declarado no adapter.
